Cross-origin postMessage DOM-XSS — corporates.db.com

DOM XSS   Deutsche Bank · *.db.com · Livebook flipbook viewer

What this is. The Livebook flipbook viewer hosted at corporates.db.com/static/flipbook/<book>/ registers a window.onmessage handler with no event.origin / event.source check when loaded with ?iframe=1, and feeds the received message straight into $.parseXML → buildSitemap → $(node).attr("title") → jQuery .append('<span>'+title) — an unescaped HTML sink. The page ships no CSP and no framing restriction on that path, so any website can frame it and post a crafted book.xml whose <node title> executes arbitrary JavaScript in the corporates.db.com origin.

Click to run the live PoC (opens in a new tab). An alert("corporates.db.com") fires — arbitrary JS in the bank's origin, delivered cross-origin from this page.

How it works (what run.html does)
  1. Frames https://corporates.db.com/static/flipbook/Deutsche-Bank-China-Compass-2024/index.html?iframe=1.
  2. The flipbook posts "init" to its parent (this page) and starts listening for the book XML — with no origin check.
  3. This page replies with a crafted book.xml containing
    <node title="&lt;img src=x onerror=alert(document.domain)&gt;"/>.
  4. The viewer renders the title via .append() → the <img onerror> executes in the corporates.db.com origin → alert popup (+ a PMXSS: beacon back to this page as programmatic proof).
